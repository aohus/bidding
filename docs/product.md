## 제품 개요

건설 입찰 공고를 검색하고 관리하는 멀티 유저 웹 애플리케이션. 나라장터
(조달청) OpenAPI 를 중심으로 실시간 입찰 정보를 제공하고, 공공기관 자체
전자입찰 공고도 함께 수집한다.

**가치 제안**
> 입찰 공고 검색부터 데이터 기반의 정교한 분석, 실시간 알림까지 —
> 입찰 정보를 가장 빠르고 똑똑하게 관리하여 낙찰 확률을 극대화하는
> 원스톱 솔루션

## 타깃 사용자

| 사용자 | 핵심 니즈 |
|---|---|
| 건설·공사 업체 담당자 | 수많은 공고 중 자사에 적합한 사업을 빠르게 찾아야 함 |
| 공공 입찰 참여 개인 사업자 | 복잡한 나라장터 대신 직관적인 UI 로 정보 확인 |
| 운영 관리자 | 공고 데이터 모니터링과 알림 설정 관리 |

## 핵심 목표

- **실시간성·접근성** — 관심 공고를 놓치지 않고 확인해 기회를 선점
- **효율적인 검색** — 나라장터의 복잡한 필터를 사용자 맞춤 조건으로 단순화
- **데이터 기반 전략** — 낙찰하한율과 과거 사정율 데이터로 최적 입찰가 산출
- **통합 관리** — 입찰 일정·문서·북마크를 한곳에서 관리해 업무 누수 방지

## 기능 설계 원칙

제품 판단이 갈릴 때 아래 순서로 결정한다.

1. **Efficiency First** — 원하는 정보를 찾는 시간을 최소화한다. 클릭 수와
   입력 단계를 줄이는 쪽을 택한다.
2. **Information Hierarchy** — 중요도에 따라 정보 위계를 명확히 해 시각적
   피로도를 낮춘다. 한 화면에 모든 것을 보여주지 않는다.
3. **Reliability** — 정확한 데이터와 법적 기준을 다루는 서비스다. 추정값과
   확정값을 UI 에서 구분하고, 데이터 출처를 명시한다.

### 데이터 신뢰성에 대한 구체적 기준

- 개찰 전 **예상** 사정율과 개찰 후 **확정** 예정가격은 섞어 표시하지 않는다.
- 외부 API 가 제공하지 않는 값을 추론해 채우지 않는다. 비어 있으면 비워 둔다.
  (기관마다 제공 필드가 달라 억지로 맞추면 사용자가 "없는 정보"를
  "0 또는 미정"으로 오인한다.)
- 수집 실패를 "데이터 없음"으로 표시하지 않는다. 둘은 사용자의 의사결정에
  전혀 다른 영향을 준다.

## 디자인 방향

**톤 — "신뢰와 전문성"**
차분하고 격식 있는 어조. 사용자가 정보를 신뢰하고 의사결정할 수 있도록
명확하고 객관적인 문장을 쓴다. 불필요한 수식어나 가벼운 표현은 지양한다.

**비주얼 — "데이터 중심의 미니멀리즘"**
- 장식을 배제하고 핵심 데이터(입찰가, 마감 기한)에 집중시킨다.
- 텍스트와 숫자의 가독성을 우선한다 — 충분한 대비, 최적화된 폰트 크기.
- 신뢰감을 주는 블루/네이비 계열을 메인 컬러로 전문성을 강조한다.
- 모든 데이터 표시와 UI 요소를 정교하게 정렬해 시스템의 안정성을
  시각적으로 체감시킨다.

**브랜드 성격 — "노련한 전문가"**
수많은 입찰 데이터를 꼼꼼하게 분석해 최적의 해답을 제시하는 전문가.
복잡한 정보는 체계적으로 구조화해 제공하고, 혼란을 주지 않는다.
